## 2. Path Tracing cost: what the code actually does (ENGINE VERIFIED)
* **Rays per pixel:**
  * One primary path per pixel; PT primary visibility comes from the G-buffer.
  * `PTRGS` has 23 `TraceRay` sites (12 in the SER variant): continuation rays (flags 528) and shadow or visibility rays (flags 12/28), per bounce.
  * Bounce counts are URT rows (Geometry Bounces, Hair Bounces). No sample-count or ray-resolution variable is read; DLSS internal resolution is the only resolution lever.
* **Light sampling:**
  * At **every path vertex** the shader loops over **every PT light**. Each light is 4 × 16-byte loads plus weight math (weighted reservoir sampling), unrolled ×8. One light is then chosen and one shadow ray is traced.
  * The light count comes from `0x1c1fdd0`: `min(list, 256)`, where 256 is a code immediate. There is no variable.
  * The list is built by `0x1c717b0`: up to 4 special lights, then the visible point and spot lights in list order, skipping negligible ones.
  * ⇒ **Implemented: PT: Light Limit.**
* **Scene geometry:**
  * The PT TLAS is filled by the proximity gather `0x1cf4830`. An object is added if it is inside the PT box (**PT: Scene Range**, already a URT row) and either its diagonal exceeds *BigObject* or `diag² × scale > angle² × distance²`.
  * In Normal RT, *angle* = `ProximityTLASObjectAngleSize` (0.1) and *BigObject* = `ProximityTLASBigObject` (15).
  * In **Path Tracing both are replaced by the constant 1e-4** (`0x1cf2a20`), so every object in the box goes into the PT TLAS, however small or far.
  * ⇒ **Implemented: PT: Small Object Culling.**
* **Hit shaders:**
  * `AnyHitTrees`, `GbufferAnyHit` and `OcclusionAnyHit` sample alpha at mip `min(10 × t, CB19.z)`. `ClosestHit` samples albedo at the fixed mip `CB19.y`.
  * For PT these come from `ReflectionsRadianceMipLevel`, which **PT: No Blue Glow** already sets to 10, and from `ReflectionsAlphaTestMipLevel`.
  * The latter is the variable of the V5.2 RC3 row you measured with no gain, so it is **not repeated**.
* **Radiance cache (SHaRC):**
  * It is used only when `PTUseSHARC` is on (`0x1c1e97e`); the code default is off. If its buffers are missing, the game falls back safely (`0x1eefcd0`).
  * Your `rendering.ini` files decide its state. R7 logs it once in PT (read-only), which also tells whether **PT: Radiance Cache Density** can act on your setup.
* **Denoising:** NRD is skipped under RR; RR's own cost is not URT-controllable.
* **Hair:** `PTHairPrepassRGS` and hair hit groups were not touched (Orange Hair Fix).

## 3. New in R7 (EXPERIMENTAL section; Native / Auto by default; no Quick Preset; all live)
| Setting | Mechanism | Native | Values | Benefit (expected, unmeasured) | Trade-off | Applies | Scope | Verification |
|---|---|---|---|---|---|---|---|---|

Both code edits:
* are written only through a writer the runtime registers (`VirtualProtect` + `FlushInstructionCache`); without it they stay native;
* are never written over a value they did not write (another mod's patch is left alone and logged);
* are restored on Native / Auto, on leaving PT, on Master Off, on an invalid setting and at shutdown;
* do not touch `dx12user.settings`, any PT shader, the PT library identity Orange Hair Fix recognises, or any startup path, so they cannot cause a startup crash loop.

## 4. Promising candidates not implemented (precise blockers)
| Candidate | Why not now | What would close it |
|---|---|---|
| `ShadowsTlas` / `RadianceTlas` / `RTAOTlas` | Each selects one of two TLAS descriptors (`+0x724` / `+0x72c` in `0x1ef0970`). Which one is smaller cannot be proven statically. | A GPU capture (Nsight Graphics or PIX) of one Normal RT frame, showing both TLAS instance counts. |
| `InlineRTAO` | Uses the "DXR Inline Occlusion PSO" for Normal RT AO. It is unknown whether that PSO is created when the game starts with it off (`0x1ef0adf`). | Static trace of the PSO creation (next round), then a restart-guarded test like Async GI Classification. |
| `UseUniversal*AHS`, `UseUniversalBaryModeCHS` | Switch to the `AnyHitUni*` / `ClosestHitUni*` shaders: state-object topology. The direction of the effect is unknown. | A restart-guarded A/B test. |
| `RayGenType` | A ray-generation variant read by 7 passes; the alternatives' semantics are not established. | Further static work. |
| `PTBaseAngleForGradient` | PT ray-cone texture LOD. Same bandwidth class as the radiance mip PT: No Blue Glow already raises. | Measurement with No Blue Glow on and off first. |
| `PTAODenoisePasses`, `PTEnableGlobalOcean`, `RT_Cull_Less_Than_DiagSize` | Small or situational, or class identity not established. | Next round. |
| PT light *importance* ordering | The light limit keeps list order. Choosing by importance would need a code hook in `0x1c717b0`, larger than this round's safety budget. | Design work. |
| SER, checkerboard RTAO, low-Q radiance, shade culling, async passes | Already on natively. | None. |

## 5. Examined
* **Executable:**
  * the PT main pass `0x1c1e1a0`;
  * light builder and upload `0x1c717b0` / `0x1c1fdd0`;
  * PT constants `0x1ef2340`;

  * render-interface vtable `0x382a950` (dispatch, pipeline, SER, SHaRC update);
  * proximity TLAS filter and gather `0x1cf2a20` / `0x1cf4830`;

  * SpeedTree RT flags `0x1cea470` / `0x1ce3a90`;
  * HBIL `0x1c2d4c1`;
  * NRD and RR gating;
  * AS configuration `0x1ee97d0`.
* **Shaders:**
  * all 441 DXIL modules in the executable were extracted (`tools/research/dxil_extract.py`), including the 65 DXR libraries (both shader sets);
  * `PTRGS`, `AnyHitTrees`, `GbufferAnyHit` / `OcclusionAnyHit` and `ClosestHit` were analysed (`dxil_dlfix.py` makes older-DXIL modules readable by LLVM 18; analysis only).

## 6. Remaining gaps and what would close them
* **Light count:** the real light count in your scenes, and which TLAS is smaller. Provide **one GPU capture** (NVIDIA Nsight Graphics frame capture, or PIX for Windows) of a PT frame at night in Novigrad and one Normal RT frame. It is optional; nothing in R7 depends on it.
* **SHaRC state:** your `bin\config\base\rendering.ini` and `bin\config\platform\pc\rendering.ini`. This is optional; the R7 log line answers it.
* **No further shader binaries are needed:** every RT and PT shader is inside `witcher3.exe`. The supplied DXC, D3D compiler and Streamline DLLs are not used by URT, so they cannot change FPS.

## 7. Gameplay test plan (all EXPERIMENTAL rows; one setting at a time)
**Setup:**
* RTX 4080, Frame Generation off for baselines.
* Same save, same 60 s route.
* Record rendered FPS, 1 % lows and GPU frame time.
* Compare each setting against Native / Auto.

**Steps:**
1. **First start after installing:** the log shows "diagnostic: the game's PT radiance cache (SHaRC) is on/off" once you enter PT. Keep that line; it decides whether PT: Radiance Cache Density can work on your setup.
2. **PT: Light Limit**, Novigrad at night or a lit interior: Native → 128 → 64 → 32 → 16.
   * Watch for lamps or torches that stop lighting.
   * Expect little change in daylight wilderness (few lights).
3. **PT: Small Object Culling**, Novigrad streets and a cluttered village: Native → 1 % → 2 % → 5 % → 10 %. Watch for small objects losing their PT shadows at a distance.
4. **RT/PT vegetation rows (R6):** forest and fields, reloading the area after each change.
   * Grass Density 0.50 / 0.25;
   * Static Trees On;
   * Grass Wind Off;
   * Billboard Updates Off on a vista.
5. **Normal RT with HBIL on:** HBIL Samples 8 / 4, then HBIL Directions 2.
6. **Stability:** 15 minutes in PT with every EXPERIMENTAL row at its strongest value, including a PT ↔ Normal RT switch and a save load.

**Recovery:**
* Every EXPERIMENTAL row is live: Native / Auto or Master Off restores the game's values and code immediately.
* None of them runs at startup, so none can cause a startup crash loop.
* If anything misbehaves, send `bin\x64_dx12\UltimateRefinedTracing.log` and the Windows Event Viewer entry.
