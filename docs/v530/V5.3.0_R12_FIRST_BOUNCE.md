## 2. What runs per pixel at one bounce (STATIC)
**Primary visibility is not ray traced.** The ray generation reads the raster G-buffer (`GBuffer0/2`, `DepthMap`, `WorldNormalMap`) for the first surface. The one pre-loop TraceRay runs only for stencil class 131, which is rare. So no primary-ray saving exists.

**Loop iteration 0 (the only iteration at one bounce):**
1. **Lobe choice (diffuse or specular).**
   * The diffuse probability is the diffuse share of the surface's energy, `lum(albedo·(1−F)) / (that + lum(F))`, clamped to 0.05–0.95. In the stratified mode it is clamped to 0.25–0.75 instead.
   * The specular branch divides by `1−p`.
2. **The bounce ray** (`RAY_FLAG_CULL_BACK_FACING | SKIP_PROCEDURAL`, tmin 1e-4).
   * The closest-hit shaders (separate libraries: ClosestHit, Terrain, Trees, Hair, Uni*) evaluate the hit material.
   * Alpha-tested geometry runs any-hit.
3. **Shading at the bounce hit**, with next-event estimation:
   * a sun/moon shadow ray (flags 12 or 28, sampled cone, tmax 1e28);
   * a local-light shadow ray (flags 12, tmax = light distance);
   * a second code path for other materials with the same ray kinds.

**Output:**
* the sampled lobe's radiance (clamped to a maximum component of 10) and hit distance;
* diffuse → `RTGBufferA`, specular → `RTGBufferB`;
* DLSS Ray Reconstruction consumes both.

**Consequence:** at one bounce, almost all PT ray work per pixel is one bounce ray, its hit shading and about two shadow rays. Most pixels take the diffuse lobe. Removing that work for a share of the diffuse samples is the strongest lever below one bounce that adds no rays and needs no new resources.

## 3. Module 2: PT: First Bounce Diffuse Coverage (EXPERIMENTAL; Native / Auto = 100 %, 75 %, 50 %; next start; no Quick Preset)
**The edit** (variant library; text pass `urt_dc_patch_diffuse`, after module 1 and Orange Hair Fix's hair patch):
1. **Drop decision.** In the lobe-decision block of iteration 0, a pixel whose sample took the diffuse lobe, and which this frame's pattern drops, branches straight to the loop exit.
   * The exit is the one the game itself uses for an invalid normal: zero radiance and hit distance 0.
   * Nothing is traced or shaded for it.
2. **Patterns:**
   * **75 %:** a 2×2 quad, one pixel dropped per frame in turn.
   * **50 %:** a checkerboard alternating every frame.
3. **Unbiased weighting.** The kept pixels' diffuse colour (the normal-branch `RTGBufferA` store, after the game's clamp) is multiplied by 4/3 or 2. Per pixel, the average over 4 or 2 frames equals the native result.
4. **Unchanged:**
   * specular samples, hair, the hit distance of kept samples, and every other output;
   * iteration ≥1, so module 1 combines independently.

**Level transport:** bits 18–19 of URT's CameraCB bounce word (gate `0..15 << 16`). URT's normal library reads bits 0–15, and module 1 reads bits 16–17.

**Variant:** one library carries both modules and the hair patch. It is built when either option is set; with both Native, the unchanged URT library is used.

**Startup guard:** each option has its own record. Both are decided at ASI load and proven after 10 minutes of RT/PT. A start that cannot prepare the shader marks pending records as failed.

**Expected (not measured):** fewer bounce rays, hit shaders and shadow rays in proportion to the dropped diffuse samples. Diffuse indirect light gets noisier, which Ray Reconstruction accumulates over 2–4 frames. Warp divergence means the saving is less than the ray share.

**Log proof:**
* `PT: First Bounce Diffuse Coverage requested (level N)`
* `PT: First Bounce Diffuse Coverage 75% active: variant PT library validated (N bytes) and installed`

## 4. Candidates investigated, not implemented in R12
| Candidate | Finding |
|---|---|
| Primary-ray savings | None possible: primary visibility is raster (§2). |
| Shadow-ray coverage at the bounce hit (sun / local light) | Feasible with the same mechanism: the shadow-ray sites, their flags and the "miss → lit" test are mapped (STATIC). An unbiased version needs the light's contribution scaled after the visibility test, and that contribution is spread over two shading paths. This is the next module if the R12 results justify it. |
| Closest-hit / material cost (texture LOD in hit shaders) | Lives in separate hit-group libraries (both slots exist). It needs a second shader-replacement path; deferred. |
| Shorter bounce rays (tmax) | Misses return the sky, so cut rays would brighten valleys such as Kaer Morhen's. Biased; rejected. |
| Opaque foliage for bounce/shadow rays | R8 measured no gain; rejected. |

## 7. R12 FIX1: why the variant was not built in game, and the repair
**Owner's log (build 1090142, level 2):** `PT shader coverage options could not be prepared …`, within the same second as the request.

**Cause: stage 5, the module 2 text pass** (OFFLINE reproduction).
* At runtime the passes edit the game DXC's disassembly. DXC prints with its LLVM 3.7 printer:
  * block labels as `; <label>:908`;
  * handle loads with typed pointers (`%dx.types.Handle* @…`).
* The offline tests used LLVM 18 text, which prints `908:` and `ptr @…`.
* Module 2 located the loop header, the exit block, the lobe block and the RTGBufferA/B loads by those LLVM 18 spellings, so it found no anchor and the build stopped there.
* Module 1 and the Orange Hair Fix port never depend on those spellings, which is why R11 worked in game.

The R12 source, on the same text rewritten to DXC syntax (`tests/host/dxc37_style.py`), gives: module 1 OK, hair patch OK, module 2 FAILED. On LLVM 18 text it passes all three.

**Repair:**
* Labels and handle loads are found in either spelling.
* On the DXC-syntax text the passes now make exactly the same edits as on LLVM 18 text: identical after the same rewrite (`test_bounce501`).
* The LLVM 18 result still assembles with `llvm-as`.

**Diagnostics:** a failure now logs `PT shader coverage variant NOT built - stage <n> <name>: <reason> (urt_bounce501.c:<line>)`. The stages are:

| Stage | What it covers |
|---|---|
| 1 | Compiler objects |
| 2 | Disassembly |
| 3 | Module 1 |
| 4 | Hair patch |
| 5 | Module 2 (with the exact anchor line) |
| 6 | Assembly (with DXC's own error text) |
| 7 | Container |
| 8 | Validation (with the validator's error text) |
| 9 | Signing |
| 10 | Re-check of the signed shader (which edit is missing, in which export) |
| 11 | Slot capacity |
| 12 | Identity |

**Success** logs that the re-check of the signed shader found both edits in both PT exports:
* the drop branch, whose exit block jumps straight to the loop exit;
* the weighted diffuse store.

No safety check was relaxed. No WitcherScript change: the R12 compile (kit rev9, blob 8c48a00b) is reused.
