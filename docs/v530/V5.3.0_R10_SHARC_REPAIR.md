# V5.3.0 PRIVATE R10: SHaRC crash, root cause and repair

**Baseline:** R9 (tag `v5.3.0-private-r9`).

**Owner's R9 result:**
* SHaRC applied and the cache was allocated (4,194,304 entries).
* The game crashed while loading into gameplay.
* Geometry Bounces 2 → 1 measured 47–48 → 57–58 FPS.

## 1. Root cause (STATIC, verified on the real Patch 5.01 executable by `test_sharc_r10`)
1. **How the game picks its SHaRC shaders.** With `PTUseSHARC` on, the SHaRC dispatch (`0x1eefcd0` → `0x1ef0010`) reads the current frame's constants at `ri + frame×0x2200 + 0x300`. It uses the **registered** ray-generation shaders `PTRGS_SharcUpdateFinal` / `PTRGS_SharcQueryFinal` (raygen 0x13 / 0x14) only when all of these words hold:

   | Word | Value | Written by |
   |---|---|---|
   | +0x210 | 2 | native constant, `0x1ef29e1` |
   | +0x214 | 1 | native constant |
   | +0x380 | 4 | native constant, `0x1ef2f6c` |
   | +0x384 | 1 | native constant |
   | +0x410 | 0x3efff | native constant |
   | +0x118 | 0 | from PT parameters |
   | +0x4e4 | 0 | from PT parameters |

   Otherwise it dispatches raygen **0x11 / 0x12**.
2. **0x11 / 0x12 are `PTRGS_SharcUpdate` / `PTRGS_SharcQuery`** (descriptor slot = raygen index; 0xf = `PTRGSFinal`, as the normal PT dispatch uses). No code references their descriptors (neither table copy), so they are **never registered in any state object**. Their shader-table records are empty, and dispatching them faults the GPU.
3. **URT wrote those words.** URT's PT serializer gate (`cr01_gate_windows.c`, V5.2.0) writes:
   * +0x210 = geometry | compensation << 8. That is **0x6402 even at all-native settings** (the in-function bounce bridge), because URT's PT shader decodes it.
   * +0x380 = hair bounces, when non-native.

   So whenever URT's PT shader was live, the SHaRC path selected the unregistered shaders.
4. **Likely timeline (not proven):** in the menu the gate is probably not yet armed (the native value 2 is used), and the cache was allocated there. Once the gate armed while loading into gameplay, the next SHaRC frame dispatched an empty raygen record, and the game crashed.

**Ruled out** (STATIC):
* **Allocation and fallback:** cache allocation fails safely (released, normal PT); a missing resolve PSO makes the frame fall back.
* **Lifetime:** renderer teardown releases and clears the cache (`0x1ef3c34..c7f`).
* **Downscale factor:** clamped to 1..10.
* **Orange Hair Fix:** patches the vanilla `PTRGS_SharcQueryFinal` (it was in-game verified with SHaRC); URT does not touch any SHaRC library.
* **Immersive World:** ships no DXR library.

## 2. Repair (R10)
* **Serializer gate:**
  * while `PTUseSHARC` (0x5149b40, exact Patch 5.01) is on, URT writes no bounce word (post-serialize and in-function bridge);
  * it puts +0x210 / +0x380 back to the native 2 / 4 if a value was armed before SHaRC was seen.

  URT's Geometry Bounces, Hair Bounces and Indirect-Light Compensation already do not apply under SHaRC (the game does not dispatch `PTRGSFinal` then), so nothing is lost.
* **Safety net (render thread):** with SHaRC on, after the native serializer, if the frame words would still select 0x11 / 0x12 (another mod, a debug mode), URT switches `PTUseSHARC` off before the frame is dispatched with them. Normal PT continues and the log says so.
* **New runtime proof line:** `PT radiance cache (SHaRC): frame data checked; the game selects its registered SHaRC shaders …`.
* **Unchanged:**
  * the startup guard (a crash before 10 min of RT/PT blocks the row at the next start until one Native / Auto start);
  * Master Off, Native / Auto (no write);
  * Quick Presets, the menu (no WCC compile), `dx12user.settings`, OHF, Immersive World.

## 3. Verification
* **OFFLINE:** `test_sharc_r10`, 15 checks on the real executable:
  * the selection code;
  * the serializer destination and its native constants;
  * the descriptor and index mapping;
  * no code reference to the non-Final SHaRC shaders, and one reference each to the Final ones;
  * the R9 failure reproduced on a serialized buffer;
  * the R10 gate keeping the words native;
  * the safety-net detection.
* **Full host suite:** all tests pass (TEST_RESULTS.txt).
* **NOT verified (needs the owner's run):** stability in game, FPS, image quality. The order of the safety net relative to the SHaRC check within a frame is not proven (the primary fix does not depend on it).

## 4. Recovery and test procedure
1. **With R9 still installed:** start normally. The startup guard blocks SHaRC (`startup guard: URTX_ExpPTRadianceCache=1 not applied …`).
2. **Install R10.** Set PT: Radiance Cache (SHaRC) to Native / Auto, quit, start once (this clears the guard record). Set it to On, quit, start, load the Kaer Morhen save.
3. **Log lines to check, in order:**
   * `startup override applied: URTX_ExpPTRadianceCache=1`
   * `SHaRC) is on`
   * `SHaRC) active: … allocated`
   * `frame data checked; the game selects its registered SHaRC shaders`
4. **Measure** FPS against Native (47–48 at Geometry Bounces 2) and check how indirect light looks.
5. **If it crashes again:** the next start blocks SHaRC automatically; send the log.
