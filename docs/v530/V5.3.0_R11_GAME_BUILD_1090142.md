# V5.3.0 PRIVATE R11: support for game build 1090142 (Steam update of 29 October 2026)

**Baseline:** R11 pre-compile (tag `v5.3.0-private-r11-precompile`). All R11 work is kept. Patch 5.01 build 1048522 is still supported, address for address.

**Evidence labels:**
* **STATIC:** read from both executables.
* **OFFLINE:** host tests on both executables.
* Nothing in this document was measured in game.

## 1. What the update changed (STATIC)
| Item | Patch 5.01 (1048522) | Update (1090142) |
|---|---|---|
| witcher3.exe SHA-256 | `2df76539…b101` | `05948d72…bae0` |
| FileVersion | 5.0.0.1048522 | 5.0.0.1090142 |
| SizeOfImage | 0x6402000 | 0x6400000 |

**Shaders:** all 735 embedded DXBC containers are byte-identical. This includes:
* the native PT library `PTRGSFinal` / `PTRGSWithSERFinal` (SHA-256 `6382…8121`);
* both copies of it, each still followed by 22144 zero bytes.

**Code and data:**
* Recompiled; functions moved by varying amounts, and .rdata / .data moved by about −0x2000.
* In every function URT uses, the instructions are identical once moved addresses are allowed for.
* The only substantive difference found is a thread-local-storage offset (`mov r15d,0x70` → `0x74`, the TLS slot base):
  * it appears in the CameraCB serializer's caller, the SHaRC dispatch and the PT shadow functions;
  * a new thread-local variable was added;
  * URT does not touch it.

**`dxcompiler.dll`:** SHA-256 `b86a738e…`. URT uses the game's own DXC only to rebuild its PT library, and the input library is unchanged.

**Effect without this port:** every earlier URT treats 1090142 as an unknown executable and runs in its ADAPTIVE tier:
* only name-resolved settings work;
* there is no PT shader, no PT bounce/hair/compensation controls, no PT Ray-Traced Shadows control, no Fast Bone Reads and no Frame Generation option;
* it is safe and does not crash.

## 2. How URT now handles it
1. **Executable identity** (`urt_exe_identity_win.c`):
   * the whole-file SHA-256 and the code-identity SHA-256 are compared with both builds;
   * the match selects the build once, at load;
   * unknown executables stay ADAPTIVE as before.
2. **Address layer** (`urt_build.c`, `urt_build_table.h`): every pinned Patch 5.01 address is written as `urt_rva(<Patch 5.01 RVA>)`.
   * On 1048522 it returns the same address, so nothing changes for Patch 5.01.
   * On 1090142 it returns the mapped address.
   * An unmapped address returns 0. Every caller verifies bytes before writing, so 0 fails closed.
   * The table has 84 entries and is generated from `tools/port/port_map_1090142.tsv`, which records how each one was found.
3. **Two fingerprints** contained rip-relative displacement bytes, which differ between builds:
   * the Frame Generation setter (`urt_fg501.c`);
   * the SHaRC diagnostic (`urt_gfx501.c`).

   They are now checked by opcode and by the computed target address. That is equally strict and works on both builds.
4. **Image size checks** use `urt_image_bytes()`.

**Not changed:**
* menu, strings, Quick Presets, WCC script, PT shader edits, Orange Hair Fix Path A, startup guard;
* any check that URT makes before it writes.

The WCC kit **v530priv-rev8 is still the right kit**: it does not depend on the executable.

## 3. How the addresses were found (STATIC, `tools/research/port_build.py`, `port_window.py`)
* **Code:**
  * the function containing each site (from .pdata) was disassembled in both builds;
  * moved rip displacements and call targets were masked;
  * it was matched instruction for instruction near the same function index.
  * Of the 29 code sites, 23 are in functions that are exactly equal. The other 6 are unique ±50–250-instruction windows around the site, in functions that differ only by the TLS offset or have no .pdata entry of their own.
* **Data:** taken from the matched instructions' rip targets.
* **Engine variables:** taken from the CVar registry by name and real category in both builds; the defaults and flags are unchanged.
* **PT library:** byte search. **RTTI and vtable:** the complete-object locator self-reference.

## 4. Verification (OFFLINE, on both executables)
**`evidence_build_port.py`** repeats every check the Windows-only modules make before writing:
* PT library registration calls and the register-helper entrance (kExactEntry);
* the CameraCB serializer call (`E8 6C 13 00 00`, aligned) and the native bounce stores 2 and 4;
* the native PT library digest, both slots and the room after each;
* the D3D12 owner globals;
* the PT shadow guard patterns (unique), the third guard branch, and all 11 PT shadow reads (opcode, trailer and target = the native Shadow variable; 15 reads of it in both builds);
* Fast Bone Reads (192 native bytes, vtable, RTTI locator);
* the Frame Generation setter;
* the SHaRC diagnostic and the render-interface vtable;
* the LODBudget slot.

**The image tests run the real module code on the mapped 1090142 image:**
* graphics rows (`v52_gfx_image_rc6`, `v53_image`, `v530_image`);
* PT and RT performance rows;
* legacy RTGI scoped bindings, the CVar index, the SHaRC selection evidence (`v5310_sharc`) and the executable identity.

**PT library:** `v5311_bounce` (R11 coverage + hair passes, `llvm-as`) and `v5311_ohf_equivalence` run on the PT library extracted from the 1090142 executable.

**`test_build_port_table.py`:**
* every `urt_rva()` literal, and every translated address table in the linked sources, is in the table;
* no raw Patch 5.01 address is left;
* the header is up to date.

**Results:**
* Patch 5.01: 52 passed, 1 expected failure.
* 1090142: 46 passed, 1 expected failure, 6 skipped. The skipped tests are Patch 5.01 research evidence for retired or documentation-only findings.
* The expected failure is the WCC menu check, which waits for the rev8 WCC results.

**Not verified:** behaviour in game on 1090142 (the same in-game validation as for R11 applies).

## 5. Other mods on 1090142 (STATIC, read-only)
* **Orange Hair Fix PT:** recognises the PT libraries by shader hash, and the shaders are unchanged. Not affected.
* **Beardmo's Immersive World:**
  * it ships no DXR library and touches no URT site (the evidence test passes on 1090142);
  * it finds its own game code by scanning;
  * if a section's code is not found, it logs `game code not found / differs, nothing patched` and leaves that section off.

  Whether its patches still apply on 1090142 is decided by Immersive World itself: check its log after the first start.
* **W3LoadFix 1.0.8:** contains Patch 5.01 addresses. It is not in the owner's recent logs.
