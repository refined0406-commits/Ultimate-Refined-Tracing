# V5.3.0 PRIVATE R9: PT Optimisation Layer, module 1 (radiance cache)

**Baseline:** R8 (tag `v5.3.0-private-r8`, kept for rollback).

**Evidence labels:**
* **STATIC:** read from the Patch 5.01 executable or DXIL.
* **OFFLINE:** host tests on the real executable.
* **OWNER-MEASURED:** in-game numbers from the owner (RTX 4080, Kaer Morhen forest, PT, FG off).

## 1. Where the forest frame goes (OWNER-MEASURED, 2026-10-29)
| Test | FPS |
|---|---|
| DLSS Quality (normal) | 55–56 |
| DLSS Ultra Performance | 93 |
| DLSS Quality, PT: Shadows Off | 59 |
| GPU usage (Task Manager), DLSS Quality | 80 % |

* **GPU-bound, and the cost scales with resolution:** about 4× fewer rendered pixels give +69 % FPS. The dominant cost is per-pixel path work.
* **Shadow rays are a small share** (about +7 % FPS with them off). This is consistent with R8: removing leaf transparency tests changed nothing.
* **What remains is the per-pixel bounce path:** bounce rays, their traversal, material and light evaluation at every path vertex.

## 2. SHaRC in Patch 5.01 (STATIC)
* **Why it is off:** `PTUseSHARC` (`Rendering/RT/PathTracer`, flags 0x200, not saved) has a code default of 0 (static initialiser `0x1cf617`). URT's R7 log confirms the owner's configuration leaves it off.
* **Who reads it:** only the PT dispatch, at `0x1c1e97e`. The SHaRC path runs when all of these hold:
  * `PTEnable`, `EnableRT` and `PTUseSHARC` are on;
  * the RT-disable flag `0x51510a0` is clear;
  * the frame is not one the engine excludes (`[+0xcc8]`).

  It then calls render-interface `vt+0x160` = `0x1eefcd0`. If that returns false, the normal PT ray-generation dispatch runs (`vt+0x190`, raygen 0xf/0x10).
* **Resources:** `0x1eefcd0` needs the inline-RT device flag `0x405aedf`, then calls `0x1ef06e0`.
  * `0x1ef06e0` allocates the three SHaRC buffers (hash entries, accumulation, resolved) **on first use**, sized from `PTSharcEntriesNumLog2` (default 22, which is about 4M entries and about 160 MB of VRAM).
  * If any allocation fails, it releases them, clears the size (`+0x220`) and returns false, so the frame falls back to normal PT.
  * **No renderer reinitialisation is needed.**
* **Pipelines:** `RGS_PTSharcUpdateFinal` and `RGS_PTSharcQueryFinal` are registered into the PT state object **unconditionally** (`0x1ee6df0`, `0x1ee6e61`). Nothing is created or rebuilt when SHaRC is turned on.
* **What it changes per pixel:** the SHaRC path dispatches `PTRGS_SharcUpdateFinal` at reduced resolution (`PTSharcDownscaleFactor`, which is what PT: Radiance Cache Density sets) and `PTRGS_SharcQueryFinal` at full resolution **instead of** `PTRGSFinal`. Query paths can end at a cache hit after the first bounce.
* **Orange Hair Fix:** v1.0.2 patches the vanilla `PTRGS_SharcQueryFinal` (hash `e22a90d3…`, 112,488 bytes).
  * Its handoff records an in-game verification on the owner's RTX 4080 with DLSS, "SHaRC + Final PT" and Refined Tracing installed.
  * URT does not touch any SHaRC library.
* **URT's PT library:** URT's edits (Geometry Bounces, Hair Bounces, Indirect-Light Compensation) live in `PTRGSFinal`, which the SHaRC path does not dispatch.
  * **While SHaRC is on, those three URT controls do not apply.** The tooltip and the runtime log say so.
  * Changing `PTRGS_SharcQueryFinal` would break Orange Hair Fix's identity match, so it is not done.
* **DLSS Ray Reconstruction:** SHaRC changes only the radiance the PT pass writes; the RR inputs and integration are unchanged (game path). Image-quality effects (bias, lag) need the owner's visual check.

## 3. Module: PT: Radiance Cache (SHaRC) (EXPERIMENTAL; Native / Auto by default; no Quick Preset)
**Values:** Native / Auto (the game's value is untouched) or On.

**Mechanism:** the URT boot step writes `PTUseSHARC` = 1 once at startup, through the existing boot-row owner (compare-and-swap from the native value; a value set by the game or another mod is left alone).

**Safety:**
* **Session-fixed:** no live switching.
* **Startup guard:** a session that ends within 10 minutes of RT/PT play blocks it at the next start.
* **Master Off at start:** nothing is written.

**Runtime proof** (log lines, all in `bin\x64_dx12\UltimateRefinedTracing.log`):
1. **Requested and applied:** `startup override applied: URTX_ExpPTRadianceCache=1`
2. **Guard:** no `startup guard: … URTX_ExpPTRadianceCache` line.
3. **The game's state:** `diagnostic: the game's PT radiance cache (SHaRC) is on`
4. **The game actually took the SHaRC path:** `PT radiance cache (SHaRC) active: the game allocated it (N entries) …`
   * This is read from the game's own render interface (`[0x5c92af0]+0x220`), after checking:
     * the vtable (`0x382a950`);
     * the two fingerprinted code sites (`0x1c1e97e`, `0x1ef0870`);
     * that the pointer is plausible.
   * The cache is allocated only by the SHaRC dispatch path, so this line proves the path ran.
   * If it does not appear within 60 s of PT, the log says "did not allocate it … not used this session".

**Trade-offs:**
* Indirect light can lag or be slightly biased (it comes from the cache).
* About 160 MB more VRAM.
* URT's Geometry Bounces, Hair Bounces and Indirect-Light Compensation pause while it is on.
* PT: Radiance Cache Density (existing row) becomes effective while SHaRC is on.

**FPS effect:** unknown until measured. The update pass adds work at 1/25 of the pixels (factor 5); the query pass can stop paths early. No FPS claim is made.

## 4. Retired: RT/PT: Solid Distant Foliage
* The owner's test with the modified shader confirmed active in the log (`URTX_ExpRTSolidFoliage=4`) showed no change at 5, 10, 20 or 30 m.
* The row is removed before the R9 compile. `urt_foliage501.c` and its host test stay in the repository as the descriptor-swap building block, but the module is no longer linked into the ASI.

## 5. Next modules (depend on the R9 measurements)
1. **Bounce share:** PT: Geometry Bounces at its lowest value, with SHaRC Off. If FPS jumps, bounce paths dominate and SHaRC and reduced-bounce work are the right direction.
2. **Reduced-rate indirect** (secondary bounce traced on a pixel subset, reconstructed by RR's temporal accumulation):
   * this needs a `PTRGSFinal` edit;
   * Orange Hair Fix matches URT's PT library by hash, so it needs a coordinated Orange Hair Fix update (owner's project);
   * investigate after (1).
3. **Not feasible:**
   * lower-resolution PT dispatch (RR guide-buffer sizes are tied to the render resolution);
   * opacity micromaps (R8 report).
