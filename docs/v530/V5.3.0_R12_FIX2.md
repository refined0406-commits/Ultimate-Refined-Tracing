## 2. PT: First Bounce Diffuse Coverage: moved, 75 % retired
* **Position:** Path Tracing section, directly beneath PT: Geometry Bounces. It is no longer EXPERIMENTAL.
* **Choices:** Native / Auto (default) and 50 %. In no Quick Preset (unchanged).
* **The 50 % shader edit is byte-for-byte the R12 FIX1 edit** (shader level 2 in bits 18–19; `urt_dc_patch_diffuse` unchanged).
* **New key `URTX_PTDiffuseCoverage`** (saved 0 = Native / Auto, 1 = 50 %).
  * Why a new key: the game saves an OPTIONS row as its option index. With 75 % removed, "50 %" becomes option 1, which under the R12 key meant 75 %. Re-using that key would have turned a saved 75 % into 50 %, a shader the user did not choose.
  * **The R12 key `URTX_ExpPTDiffuseCoverage` is retired.** It is never read, so no value saved under it (75 % or 50 %) can activate a shader. If it holds a value, the log says so once and asks to choose 50 % again in the new position. Its guard record is dropped. The line in `dx12user.settings` is left in place (the file is never reset).
  * **Owner action once:** choose 50 % again under PT: Geometry Bounces.
* **Tooltip (18 languages):** reduces first-bounce diffuse sampling; improves PT performance by reducing rendering work; may add indirect-lighting noise; "50% is recommended alongside PT: Geometry Bounces set to 1 for maximum FPS in our tested configuration"; restart required. No guarantee of gains or identical quality.

## 3. Startup guard redesign (`urt_startup_guard.c`)
**Problem in R11/R12:** a record became "proven" only after 10 minutes of RT/PT rendering. Any session shorter than that, including a normal quit, counted as a crash at the next start, so the option was blocked after a quick restart.

**New design: session state, not elapsed time.**

| State | Meaning |
|---|---|
| `pending` | applied this session; the session has not ended cleanly yet |
| `clean` | the last session that used it ended with a clean game exit |
| `proven` | 1 minute of RT/PT rendering with it (was 10 minutes) |
| `retry` | the last session ended without a clean exit and without proof: suspected crash |
| `retrying` | the one automatic retry after a suspected crash is running |
| `failed` | the retry was interrupted as well |

**Clean exit detection:** `DLL_PROCESS_DETACH` with `lpReserved != NULL` (normal process termination). URT then marks only the keys this session applied as `clean`. File I/O only; the paths are prepared earlier, so nothing is loaded inside DllMain.

**Transitions at each start:**
* new value, `clean` or `proven` → applied;
* `pending` (no clean exit, no proof) → **not applied this start**, record `retry` (suspected crash);
* `retry` → applied once more (`retrying`);
* `retrying` again interrupted → `failed`: off until the owner chooses Native / Auto for one start;
* Native / Auto → the record is cleared and the native shader is used.

**What the owner sees:**
* Quit and restart immediately: works, every time (requirements 1, 2, 8).
* A real crash with the new shader: the next start runs native, the start after that retries once automatically; a second crash turns it off. No crash loop (3, 4).
* Other settings are never touched; only the one row is held back (5). Native / Auto always restores (6).
* Every decision is logged with its reason: new, clean exit, proven, suspected crash, retry, turned off, still off (7).
* No shader verification, executable identity or resource check was changed (9).

**Documented limitation:** a terminated or frozen process, a GPU device removal that ends in a kill, or a power loss never runs the clean-exit mark. But if a crash handler ends the process through a normal `ExitProcess`, URT sees a clean exit and keeps the option. In that case, and always: choose Native / Auto and restart to get the native shader back.

**Scope:** the same rules apply to every guarded row: RT Animated Geometry Trace Mode, Async GI Classification, and the three PT shader coverage rows (decided at ASI load; a late start judges them the same way).

## 4. The delayed FPS rise (56 → 60+ after a few seconds): investigation (STATIC)
Every URT timing path between ASI load and stable gameplay was read:

| Path | Timing |
|---|---|
| PT variant library (build, validation, install) | at ASI load, before the renderer exists. Your FIX1 log shows it installed before the switch to Path Tracing. |
| Boot-stage rows (async flags, trace mode) | before ray tracing initialises |
| Runtime worker | polls the renderer mode every 50 ms; live rows are written within 50 ms of the first PT frame |
| Coverage level in the frame data | written by the CameraCB serializer gate on every PT frame, from the first one |
| Deferred / timed URT work | none that changes rendering. The only timed item is the guard's 1-minute proof, which writes a text file. |

**Finding:** no URT-owned delay was found. Nothing was changed on speculation. The likely causes are outside URT: texture and geometry streaming after loading, BLAS builds for newly streamed objects, the game's shader cache, Ray Reconstruction history, and GPU clocks settling.

**New activation proof** (render thread, logged once): `URT: PT shader coverage in effect: Path Tracing frames now carry the variant's coverage level`. Its timestamp shows when the optimisation reached rendered frames. If it appears seconds before the FPS rises, the delay is not URT's.

## 5. Module 3: PT: Bounce Sun Shadow Coverage (EXPERIMENTAL; Native / Auto, 50 %; next start; no Quick Preset; NOT tested in game)
**Mechanism (STATIC):** at a bounce hit, each PT export traces three directional (sun / moon) shadow rays, all with tmax 1e28 and visibility `select(miss, 1.0, 0.0)`.

**The edit** (`urt_sc_patch_shadow`, after module 2):
* **50 %:** for half of the pixels per frame (pattern `x ^ y/2 ^ frame/2`), the three rays get instance mask 0. DXR then traverses nothing, so there is no BVH walk and no any-hit work.
* Their visibility is 0. The traced half's visibility is ×2.
* The result is unbiased per pixel over 4 frames (Russian roulette), including within module 2's kept frames.

**Unchanged:**
* local-light shadow rays, bounce rays, hit shaders, specular;
* modules 1 and 2 (identical edits; checked);
* the number of TraceRay calls and loops.

**Expected effect (not measured):** less traversal work at bounce hits, mainly outdoors in sunlight, with more sun-shadow noise in indirect light. **No FPS claim until the owner tests it.** Level transport: bits 20–21.
