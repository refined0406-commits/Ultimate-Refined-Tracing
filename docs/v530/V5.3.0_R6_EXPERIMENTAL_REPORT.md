**Baseline:** R5 (tag `v5.3.0-private-r5`, gameplay-approved by the owner).

**Inputs checked:** the supplied `witcher3.exe` and R5 source are byte-identical to the working copies (`2df76539…`, `96b7be03…`).

**Status labels:**
* **ENGINE VERIFIED:** the read site is confirmed in 5.01.
* **OFFLINE VERIFIED:** host tests pass on the real executable.
* **PERFORMANCE VERIFIED / GAMEPLAY APPROVED:** none yet; your tests decide.

No figure here is a measurement.

## 1. What was investigated
* **Engine variables:**
  * 513 variables in the RT, PT, RTXGI, NRD, Async and DLSS categories, with every code access verified by disassembly.
  * 48 are already owned by URT, 425 are read by the game, and 42 are never read.
* **Path-tracing shaders:**
  * The four PT ray-gen libraries were extracted from `witcher3.exe` and disassembled with LLVM 18 (`llvm-dis`). This is read-only; no DXC run and no compiler.
  * A dominator analysis (`tools/research/dxil_gates.py`) lists, for each of the 23 `TraceRay` calls in `PTRGS` (12 in the SER variant), the constant-buffer fields that gate it.
  * Those fields were mapped back to engine variables through the PT constants writer (`0x1ef2340`).
* **DXR inventory:** all 64 DXR libraries (PT, RTGI probes, radiance/reflections, shadows, AO, every hit and miss shader) are embedded in `witcher3.exe`, so shader analysis needs no further files.
* **Supplied DLLs:**
  * `dxcompiler.dll` and `dxil.dll` are DXC 1.9.2602.17. URT ships validated precompiled DXIL and never calls them, so replacing them cannot change FPS.
  * `sl.interposer` is Streamline 2.14.1. URT does not hook DXGI/D3D12, so there is no interaction.

## 2. New EXPERIMENTAL controls
All are live engine variables in URT's existing ownership table:
* compare-and-swap writes;
* never saved to `dx12user.settings`;
* renderer-scoped; Master Off and Native / Auto restore byte for byte;
* no AS build-flag or startup-only change, so no restart and no startup guard is needed;
* no Quick Preset.

## 3. Path-tracing shader findings (no shader was changed)
* **Gating fields:** `TraceRay` calls are gated by:
  * a frame light count (CB row 54): gates 6 of 11 traces in `PTRGS`;
  * `PTLocalLightMaskEnable` (row 98);
  * the hair modes: `PTHairShadowOcclusionMode`, `PTHairShadowOriginSpreadScope`, `PTHairShadowOriginSpread`, `PTHairGameLightIndirect` (rows 83–85);
  * frame data;
  * a debug draw mode.
* **Hair modes: not exposed.** They gate the hair self-shadow/indirect traces, exactly what Orange Hair Fix tunes. Exposing them would compete with OHF's look, and OHF compatibility is non-negotiable.
* **Light count: not exposed.** The light-count field is filled through a setter (`0x1c2e160`) with no direct caller. The cvar that caps it, if any, was not traced in this round. Next step: trace the setter through the RT frame-data copy. It is the most promising remaining PT lever.
* **Bounces, SHaRC density, scene range, PT RT shadows and AO quality:** already URT controls.
* **No sample-count or ray-resolution variable is consumed by the PT shader:** `PTSamplesPerPixel` is never read, so there is no honest "PT resolution" control. DLSS's internal resolution remains the resolution lever.
* **Any PT shader edit changes the protected library's identity,** which Orange Hair Fix recognises. Shader-level PT changes therefore need a coordinated OHF update and are not in this build.

## 4. Investigated and not added (evidence)
* **NRD settings (about 60):** irrelevant with DLSS Ray Reconstruction, which your `dx12user.settings` has on; RR replaces NRD. Changing them would do nothing on your setup.
* **Async compaction:** removed in R5; not reactivated.
* **`UseUniversal*AHS` / `UseUniversalBaryModeCHS`:** real alternative "universal" any-hit/closest-hit shaders exist (`AnyHitUni*`, `ClosestHitUni*`). They change the DXR state-object topology, so the effect and risk need an isolated restart-guarded test. Candidate for the next round.
* **`ActiveSubBlocksRatio`:** an output the game writes, not a control.
* **`RtRadianceEnableLowQ`, `EnableSER`, `UseShadeCulling`, `ProcessProbesGridCheckerboard`:** already on by default.
* **`MeshRenderingDistanceScale`, `GrassDistanceScale`, `CascadeShadowmapSize`:** native graphics settings; never overwritten.

## 5. Gameplay test plan (RTX 4080; Frame Generation off for baselines; one setting at a time)
**Measure:** rendered FPS, 1 % lows and GPU frame time over 60 s in the same save and route.
1. **PT forest (Velen/White Orchard):** RT/PT: Ray-Traced Grass Density at Native → 0.50 → 0.25, reloading the area each time (load the save). Expect the largest PT effect here.
2. **Same forest, windy:**
   * RT/PT: Static Ray-Traced Trees On (reload the area);
   * then RT/PT: Ray-Traced Grass Wind Off.
   * Watch GPU frame time and CPU-bound 1 % lows.
3. **Wide vista (Skellige or a hill):** RT/PT: Ray-Traced Billboard Updates Off (reload).
4. **Normal RT with HBIL on:** RT: HBIL Samples 16 → 8 → 4.
5. **Stability:** 15 minutes with all five on.

**Recovery:**
* All five are live and need no restart. Native / Auto or Master Off restores the game's values immediately; vegetation rows refresh fully after an area reload.
* None of them touches the startup path, so none can cause a startup crash loop.
