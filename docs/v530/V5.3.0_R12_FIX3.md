## 4. Reliability audit: do the optimisations stay active? (STATIC + OFFLINE)

**How the coverage reaches the GPU:**
1. At ASI load the variant library is written once into both PT shader slots.
2. Those slots are in `.rdata`, a read-only image section, in both executables (checked).
3. The game never writes them. It creates its PT state objects from those bytes every time, including after renderer changes, settings changes and save loads.
4. The coverage level is a fixed value for the session.
5. It travels in the CameraCB word that URT's gate writes on every PT frame.

**State changes checked:**

| Event | Effect on the coverage options |
|---|---|
| Quick Presets (all 4) | Their entries contain only RTGI quality/performance rows (menu checked). They cannot change either coverage option or Geometry Bounces. |
| Editing other controls, settings save/reload, menu open/close | Republishes Geometry / Hair / Indirect-Light only; the level is not part of the menu state. |
| Geometry Bounces Native / Hair / Indirect-Light at any value | Level still carried: the in-function bridge word always includes it (verified on 400 000 simulated frames). |
| Save load, area load, fast travel | No URT code runs on these. The gate runs on every PT frame. |
| Renderer change | Raster or Normal RT frames are native by design; PT frames carry the level again from the first frame. |
| Master Off / On | Native while Off (by design); back with On. Saved preferences are kept. |
| Game's SHaRC turned on | URT's PT words stay native (R10 protection), so the coverage pauses. It is now logged; it is off in your configuration. |
| Restart | Decided again at ASI load (startup guard, section 5). |

**Finding: no URT-owned way for a selected coverage option to switch off silently** was found. But until now, a pause would not have been visible in the log.

**New diagnostics (worker thread only):**
* **Coverage state:**
  * logs `in effect`, or `paused: <reason>` (SHaRC on / library not live / Master Off / values not staged);
  * logged only when the state changes.
  * The render thread only increments atomic counters.
* **Shader slot re-check** at every switch into Path Tracing: both slots still hold the installed, validated variant (read-only). A mismatch is logged as a WARNING.
* **Restoration:** none implemented. The slots are read-only and the game never re-registers different bytes into them, so there is nothing to restore. The re-check would show it if that ever changed.

## 5. Permanent FPS loss during a session (58–59 → 55–56 until restart)

**URT-owned mechanisms audited (STATIC):**
* **Allocations:**
  * all one-time, guarded by `if (!buffer)`: CVar index, settings snapshot, variant library, shader backups (freed at commit), gate relay page;
  * none per settings event, save load or renderer change.
* **Threads:** one worker thread for the whole session.
* **Hooks:**
  * installed once (CAS-guarded: `g_attempted`, the gate's owned call site);
  * never re-installed, so callbacks cannot be duplicated.
* **Files:** every handle is closed in the same function.
* **DXC objects:** one variant build at load; every COM object is released.
* **Engine variables:**
  * written with compare-and-swap only when the value differs;
  * restored to the game's value outside the row's renderer, with Master Off and at shutdown;
  * session-fixed rows (boot / startup) are applied once.
* **Repeated work:** a settings event re-reads URT's files and re-publishes; it allocates nothing and writes nothing when nothing changed.

**OFFLINE proof** (stress test on the real image of both executables):
* 30 simulated restarts × 600 random steps;
* about 4 700 settings events, 3 000 renderer changes and 1 500 Master toggles.

The checks:
* no stray byte;
* live rows native out of scope and with Master Off;
* a repeated callback writes nothing;
* bounded ownership;
* clean state after each shutdown;
* no record of a retired key.

**One robustness fix:** if Windows ever stopped delivering settings-change notifications, the worker stopped and released every URT value for the rest of the session. It now re-arms the notification once and logs it.

**Conclusion:** no URT-owned accumulation, leak or stale state was found. **That does not prove the cause is outside URT.**
* Candidates outside URT include:
  * GPU memory pressure (streamed textures, geometry and acceleration structures growing until Windows moves data out of video memory);
  * acceleration-structure fragmentation;
  * driver behaviour;
  * other mods.
* No engine patch was made on speculation.

**New evidence line (every 5 minutes and at each renderer change):** `URT: session snapshot (...)`. It records:
* renderer and Master state;
* the game's GPU memory use and its budget (read-only, through the system `dxgi.dll`; `OVER BUDGET` if exceeded);
* process memory;
* PT coverage frames carried and not carried;
* the shader slots' status;
* the engine values URT holds and the URT writes so far;
* settings events and renderer changes.

**Owner test (no extra software):**
1. Start the game and go to the benchmark spot. Note the FPS.
2. Play as normal (settings, saves, travel) for 30+ minutes.
3. Return to the spot and note the FPS.
4. Send `UltimateRefinedTracing.log`.

**Reading the log:**
* Growing GPU memory, or `OVER BUDGET`, while URT's values and coverage stay the same points to memory pressure.
* A change in URT's own state points to URT.

## 6. Module 4 (EXPERIMENTAL): PT: Bounce Local Light Shadow Coverage

Native / Auto default, no Quick Preset, next start. **NOT tested in game.**

**STATIC:** at a bounce hit each PT export traces one local-light (point / spot) shadow ray per shading path, with tmax = light distance.
* **Site S (flags 28):** visibility `select(miss, 1, 0)`. Half of the pixels: mask 0 (nothing traversed) and visibility 0; the other half: ×2.
* **Site B (flags 12):** the whole light evaluation runs only when the light is visible.
  * Half of the pixels: mask 0, and the branch skips the evaluation, so both the ray and the shading are saved.
  * The other half: the block's one result factor is multiplied through a phi by 2. The phi is 1 on the block's other, untraced entries.

**Properties:**
* Pattern `((x>>1) ^ y ^ (frame>>1)) & 1`: unbiased per pixel over 4 frames, also within module 2's kept frames.
* Level in bits 22–23.
* **Built only when selected.** With it off, the variant text is exactly R12 FIX2's.

**Expected (not measured):** saves work only where local lights are lit and in range (torches, fires, lamps, interiors, night). The daytime Kaer Morhen benchmark may show little.

**Other candidates:**
* Material and hit-shader cost: separate hit-group libraries. Deferred.
* Lower diffuse coverage: not added.
