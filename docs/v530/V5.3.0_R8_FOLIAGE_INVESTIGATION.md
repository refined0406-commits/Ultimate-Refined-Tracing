# V5.3.0 PRIVATE R8: dense-forest RT/PT investigation

**Baseline:** R7 (tag `v5.3.0-private-r7`, kept for rollback).

**Status labels:**
* **ENGINE VERIFIED:** confirmed in Patch 5.01 code or DXIL.
* **OFFLINE VERIFIED:** the host tests pass on the real executable.
* **PERFORMANCE VERIFIED:** nothing in R8 yet.

No figure below is a URT measurement. The only external numbers are NVIDIA's own (§3).

## 1. Why R7 did not move the Kaer Morhen forest (54–55 FPS)
Each failure has a code-level reason. The common mistake was the same: **R7 targeted secondary work (acceleration-structure updates, light lists, small-object culling) instead of the per-ray cost of tracing through foliage, which dominates a forest.**

| R7 control | What it actually changes (ENGINE VERIFIED) | Why it cannot help this forest |
|---|---|---|
| Static Trees, Grass Wind, Billboard Updates | Per-instance BLAS *update* masks (0x1cea470, 0x1ce16f0, 0x1cea2b0) | They remove refit/update work, not ray work. Your result shows that update work is a negligible share of the frame. **Retired in R8.** |
| Ray-Traced Grass Density 0.25 | RT grass instance count (0x1ce23e0) | Grass is a small part of the forest's ray work; the cost sits in tree foliage. Kept for grassland scenes (untested there). |
| PT: Small Object Culling 10 % | Angular-size filter in the PT proximity gather (0x1cf4830) | By construction it cannot remove trees: an object whose diagonal exceeds `ProximityTLASBigObject` (15 m) is accepted before the angular test (0x1cf4b2e). Kept for clutter-heavy towns (untested there). |
| PT: Light Limit 16 | Light count of the PT light loop (0x1c20018) | A forest has few lights, so a cap of 16 removes nothing. It can still matter in lit interiors and towns at night. Kept. |
| RT: HBIL Samples / Directions | HBIL constants (0x1c2d542/54c) | Normal RT only, and only while HBIL is on. In Path Tracing they do nothing by design. Kept for Normal RT. |

Points 2, 3, 5 and 6 of your list (bypassed, negated, dependencies) are **not** the cause: each R7 control was confirmed to write and act in its own path. The cause is points 1, 4 and 7: the work they reduce is a small share, or they act on AS updates, or the dominant workload (foliage traversal) was untouched.

## 2. The real forest workload (ENGINE VERIFIED from the shaders)
* **Every PT ray runs AnyHitTrees on a leaf card:** all 16 `TraceRay` calls in `PTRGSFinal` use the GBuffer payload, contribution 0, multiplier 4. So every PT ray, shadow rays included (flags 12/28), runs the tree hit group's any-hit shader **AnyHitTrees** (`AHS_GBuffer_Trees`) whenever it meets a leaf card.
* **What AnyHitTrees does per call:** 4 buffer loads for the UVs, one alpha sample (mip `min(10 × t, CB19.z)`), and `IgnoreHit` when alpha < 1e-4.
* **Shadow rays** (accept first hit) run it **for every leaf card they cross** until one texel is opaque.
* **Bounce rays** run it for every card crossed before the nearest hit.
* **No opaque fast path:** there is no `FORCE_OPAQUE` flag on PT rays, and nothing in the engine marks foliage opaque.
* **Normal RT:** reflections (`RadianceRGS`), RTGI probes and local shadows use the same GBuffer hit groups. Sun shadows (`ShadowsRGS`) and RTAO (`AORGS`) use the occlusion payload (contribution 2), which is a different hit group.
* **How the libraries are loaded:** a static descriptor table (0x3226eb0..0x322ca60, 52 entries) is read by the generic loader `0x500040` when ray tracing builds its state objects. It passes `[entry+0x28] → [size][DXBC]` to the shader-registration helper.

## 3. Public research (summary)
* **Measured cost in a shipping PT game:** NVIDIA's Indiana Jones path-tracing write-up measured the main trace pass on an RTX 5080.
  * It took **7.90 ms with alpha-tested any-hit shaders**, and **3.58 ms (−55 %)** once opacity micromaps removed most any-hit calls.
  * The any-hit shader's own runtime was only part of the cost. The bigger part was the switching overhead between traversal and the any-hit shader.
  * For *indirect* rays they accepted a two-state (opaque/transparent) approximation.
* **Opacity micromaps are not feasible here:** they would need micromap arrays baked for every foliage BLAS and BLAS rebuilds inside the engine. URT cannot add that to Patch 5.01.
* **What R8 does instead:** it uses the same principle in the one place URT can reach safely, the tree any-hit shader. Leaves count as solid past a chosen distance.

## 4. Implemented in R8: RT/PT: Solid Distant Foliage (EXPERIMENTAL; Native by default; no Quick Preset)
**Values:** 30 m / 20 m / 10 m / 5 m.

**Mechanism:** a single comparison in AnyHitTrees. A transparent texel is skipped **only** when the hit is within the chosen distance of the ray's start; beyond it, every leaf card counts as solid.
* Shadow rays end at the first distant leaf card.
* Bounce rays stop shrinking their search through the canopy.
* Near foliage keeps exact alpha.

**Expected benefit (not measured):** fewer any-hit invocations per ray in canopies, which is the cost class in §3. It applies to:
* every PT ray;
* Normal RT reflections, RTGI probes and local shadows.

It does **not** apply to Normal RT sun shadows or RTAO (occlusion hit group).

**Trade-off:**
* Distant canopies block light as if their leaf cards were solid, so the forest floor gets darker and dappled light through distant leaves is lost.
* Reflections and bounce light see denser distant foliage.
* On-screen trees are unchanged; they come from the raster G-buffer.

**How it is built and applied:**
* **Build:** at startup, with the game's own `dxcompiler.dll` / `dxil.dll`:
  1. disassemble AnyHitTrees;
  2. make the one text edit;
  3. assemble;
  4. put back the original container parts;
  5. validate and sign;
  6. disassemble again to confirm the edit is still present.

  This is the same path as URT's existing PT library build.
* **Publish:** a compare-and-swap of the single descriptor pointer (RVA 0x322c7b8), only from the native value, only before ray tracing initialises (`0x405af14` = 128).
* **Identity check first:** the descriptor's wide strings, the flags, the 4520-byte container and its digest `9eee01b4…`.

**Safety:**
* **Session-fixed:** it applies from the next game start.
* **Startup guard:** a session that ends within 10 minutes of RT/PT play blocks it at the next start, so there is no crash loop.
* **Fail closed:** if anything fails (identity, compiler, validation), foliage stays native and the log says so.

**Compatibility:**
* Orange Hair Fix replaces only PT ray-generation libraries matched by hash. AnyHitTrees is not among them, and the PT library is not touched.
* Immersive World ships no DXR library (compat evidence).
* `dx12user.settings`, native graphics settings and Quick Presets are untouched.

**Verification:**
* **ENGINE VERIFIED:** ray payloads, hit groups, the loader and the descriptor.
* **OFFLINE VERIFIED:**
  * the edit on the real AnyHitTrees disassembly re-assembles with `llvm-as`;
  * the anchors are unique, so an ambiguous or already-patched text is refused;
  * the identity check and the swap behave correctly on the mapped executable;
  * the boot step, guard, late-start, Master Off and no-builder paths are covered (`test_foliage501`, `test_v530_image`).
* **Not yet verified on Windows:** acceptance by the game's DXC validator and D3D12. Your first start shows it in the log: "startup override applied: URTX_ExpRTSolidFoliage=…" or "could not be prepared".

## 6. Other mechanisms examined
* **Shadow and bounce ray flags (`FORCE_OPAQUE` on PT bounce rays: 528 → 529):**
  * This would remove **every** any-hit call for bounce rays, a stronger lever than R8.
  * It requires editing `PTRGSFinal`. Orange Hair Fix patches URT's PT library by exact hash, so any change there breaks Orange Hair Fix until it ships a matching update.
  * Documented only; **not built**.
* **Reduced-resolution or checkerboard PT dispatch:**
  * The PT dispatch size feeds DLSS Ray Reconstruction's guide buffers. A lower-resolution dispatch would need a new reconstruction pass, which means a new renderer stage. Not feasible in URT.
  * The existing late-specular checkerboard is a URT row already; DLSS mode remains the resolution lever.
* **Opacity micromaps:** not feasible (§3).
* **Normal RT sun shadows and AO** (occlusion hit group): the same edit in `OcclusionAnyHit` (shared library 0x33313b0 with GbufferAnyHit) is the natural next step.
  * That library is registered twice (`AHS_GBuffer` and `AHS_Occlusion`), so swapping one registration needs the per-export registration to be proven first.
  * Next round, if R8 shows a gain.

## 7. In-game benchmark plan (your tools only: in-game overlay; same save, same 60 s route, Frame Generation off)
**A. Where the forest frame time goes** (existing controls, R8 or R7 build):
1. Baseline PT, everything Native.
2. **PT: Shadows Off.** A large gain means shadow rays through foliage dominate, which is exactly what R8 targets.
3. Geometry Bounces at its lowest value: the share of bounce rays.
4. Restore all.

**B. The new row:**
1. RT/PT: Solid Distant Foliage → 30 m.
2. **Restart the game**, then load the same save.
3. Check the log line "startup override applied: URTX_ExpRTSolidFoliage=1".
4. Run the route, then repeat with 20 m, 10 m and 5 m.
5. Note the FPS and how dark the forest floor gets.

**C. Recovery:**
* Set Native / Auto and restart.
* If a start crashes, the next start does not apply it ("startup guard: … not applied"). Set Native for one start to clear it.

**Reading the result:**
* If A2 gains a lot and B gains little, the cost sits in the shadow rays' traversal itself rather than in any-hit calls (or in near foliage). R8 has then hit its limit, and the PT ray-flag change (§6) is the remaining lever, requiring a coordinated Orange Hair Fix update.
* If neither A2 nor B gains, the forest cost is shading/denoising (DLSS RR), not ray traversal.
