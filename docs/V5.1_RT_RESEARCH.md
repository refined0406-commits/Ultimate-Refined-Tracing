## 1. Method (all static, read-only, no game execution)
Research tools are in `tools/research/` and are reproducible.

* **`cvar_dump.c`, `cvar_table.py`:** list every engine configuration variable (1,732) from the registry descriptors.
  * Decoded descriptor layout (56 B): `+0` name, `+8` flags (low byte type: 0 bool, 1 int, 2 float), `+16` value pointer, `+24` registered default, `+40` type, `+48` category.
* **`xref_scan.c`, `xref_verify.py`:** find every instruction referencing each value slot.
  * Brute-force scan of RIP-relative operands, then verification by disassembly.
  * Function bounds come from `.pdata`; leaf functions without `.pdata` are bounded by int3 padding. An early version missed leaf functions and was corrected (see §6).
* **`annotate.py`, `readsites.py`, `callgraph.py`:** annotated disassembly (CVar names, string and float literals), read-site context, and a direct-call graph.
* Every address used by code is checked at runtime: exact bytes, decoded RIP targets and the pinned value RVA. On any other executable the feature stays native.

## 2. How Normal RT RTGI really works on Patch 5.01
The grid parameters are NVIDIA RTXGI DDGI volume parameters: probeMaxRayDistance, hysteresis, distance exponent, 6/14 irradiance/distance texels, normal/view bias, backface threshold. Their semantics are therefore documented by NVIDIA rather than guessed. Two volumes exist: `RTXGI/GlobalGrid` (coarse, far) and `RTXGI/Grid1` (fine, near).

**RTXGI init `0x1c617e0` chooses one of three native tiers:**

| Tier | Grid1 probes | Grid1 class. rays | Grid1 spacing | Global coverage | Global probes shaded / classified per frame | Grid1 ray budget |
|---|---|---|---|---|---|---|
| Quality (`RTGIPreset=1`) | 64x64x16 | 32 | 1.2 m | 616x616x256 | 16384 / 65536 | 524288 |
| Performance | 48x48x16 | 16 | 1.6 m | 504x504x204 | 8192 / 32768 | 262144 |
| Performance + `BalanceModeRT` | **40x40x16** | **12** | 1.8 m | 448x448x180 | 4096 / 16384 | 262144 |

`BalanceModeRT` (`Rendering/RT`) is read **only** by the two tier-constant writers (`0x1c6181c`, `0x1c615f5`). It is the console Balanced-mode tier; PC never sets it.

**Re-initialisation:**
* The per-frame `0x1c61410` (called from the RT frame function `0x1d326a0`) rebuilds the grids through the game's own teardown and init whenever `RTGIPreset` or `ProcessProbesGridCheckerboard` differs from the value the grids were built with.
* For the checkerboard, that value is a static latch byte at `0x4017c5c`. It is statically 1, compared at `0x1c61440` and re-stored at `0x1c61493`.

**Per-frame parameter apply:**
* Leaf functions `0x1c59ff0` (GlobalGrid) and `0x1c5c140` (Grid1) re-copy most grid variables from the CVars into the grid objects every frame. That covers rays, budgets, cycles, spacing, ray distance and hysteresis. Most RTGI variables are therefore live.
* Variables that are **init-only**, read only inside grid creation:
  * GlobalGrid coverage and spacing;
  * GlobalGrid MaxProbesShaded and MaxProbesClassificatedPerFrameAfterFirstPass;
  * Grid1 MaxProbesClassificatedPerFrame;
  * grid counts and texel counts.

**GPU work per frame (DispatchRays sizing):**

| Pass | Width × height (location) |
|---|---|
| Grid1 shading | `ShadingRaysPerFrameBudget` (halved by the checkerboard) × 1 (`0x1c5b93f`) |
| GlobalGrid shading | NumShadingRaysPerProbe × probes-this-frame (`0x1c5b99d`) |
| Classification | NumClassificationRaysPerProbe × probes-this-frame (`0x1c5ba1a`) |

**Safety rules (`src/urt_rtperf_core.c`, `src/urt_rtperf501.c`):**
* **Binding identity:** name + **real category (+48)** + flags + registered default. On Patch 5.01 the value slot must also equal the pinned RVA.
* **Write discipline:** writes are compare-and-swap only. A foreign value is never overwritten; the field is released instead. Native values are restored on PT, raster, Master Off, invalid preferences and shutdown.
* **Cost direction:** a control can only lower cost. Rays are only ever shortened, mip levels only coarsened, light counts only reduced. When the native value is already cheaper, URT does nothing.
* **Plausibility:** an implausible native value (NaN, a zero mip before engine initialisation, a non-bool byte) is never owned.
* **Console grid (state machine, fully unit-tested):**
  * It acts only in Normal RT, RTGI Performance, after the game's own init has produced the 48x48 tier.
  * Sequence:
    1. Set `BalanceModeRT=1`.
    2. Flip the checkerboard latch so the game itself rebuilds RTGI.
    3. Restore `BalanceModeRT=0` as soon as the 40x40 tier appears (within about 50–100 ms of the rebuild).
  * Limits: a 3 s timeout, 4 s cooldown and 3 attempts, then it gives up until the setting changes.
  * Turning the control or Master Off requests a rebuild back to the native tier. PT, raster and RTGI Quality never trigger a rebuild, and a 40x40 tier URT did not create is never touched.
* **V5 interaction:** V5's existing RTGI Performance profile recognised only the native 16-ray signature. It now also accepts 12 rays, **only** while URT's own console tier is active (`console_tier` flag). Otherwise the behaviour is byte-identical (`tests/host/test_legacy_console_tier.c`).
* **Persistence:** these are internal engine variables, not menu variables. Game persistence comes from the `user_config_matrix` menu variables (that is how URT's own group is saved). `BalanceModeRT` is additionally set only for the duration of a pulse. Optional cross-check: search your `dx12user.settings` for `BalanceModeRT` or `ProbeMaxRayDist`. Neither is expected.

**Menu, script and strings:**
* **Menu:** 1 separator + 7 rows appended at the end; the 50 existing rows are byte-identical and in place. No Quick Preset sets a new row.
* **WitcherScript, 3 additive hunks:**
  * 7 tooltip registrations;
  * 7 Master-only dependents (greyed out with Master Off);
  * 7 names in `RT_CR01_IsOwnedOption`, so edits are saved and applied immediately and the difficulty-hotfix routing still applies.
* **Strings:** 31 new keys × 18 languages. Labels are in English per the V4/V5 convention; values and tooltips are translated. No existing record changed.
* **Quick Preset behaviour:** editing a new row while a Quick Preset is selected switches the preset to Off with values kept, the same established rule as every URT control. Easy to exempt if you prefer.

## 4. Rejected or deferred (with reason)
| Candidate | Finding | Decision |
|---|---|---|
| `ShadeVisibleBlocksRatio` | Splits a fixed per-frame quota between visible and invisible blocks (`0x1c594d6`); does not reduce work | Rejected (no FPS lever) |
| Grid1 `FramesNumPerShadingCycle` / `...ClassificationCycle` | Only rotates which probes are processed; Grid1 shading dispatch is the ray budget (already a V5 control) | Rejected (no FPS lever) |
| `MeshRenderingDistanceScale` | Applied at mesh-component setup, and also read by raster code | Rejected (breaks RT/raster isolation) |
| `RTRadianceEnableCheckerboarding`, `RTAOEnableCheckerboarding` | Already on by default; the RTAO one is rewritten by the game at runtime | Rejected (no gain; conflict) |
| Emulating the console tier by writing counts/spacing directly | Counts are init-only, spacing is per-frame → mismatched grid | Rejected (unsafe); the game's own tier is used instead |
| `UseAsyncRTAO`, `InlineRTAO`, `UseAsyncCompact` (developer toggles, default off) | Change GPU queue/pipeline topology; failure mode could be a GPU hang | Deferred: needs dedicated analysis and in-game A/B before exposure |
| Lower-than-console RTGI tier (e.g. 32x32) | Needs a code-constant patch of the tier writer; allocation assumptions unverified | Deferred |
| RTGI Quality using a lower grid tier | The Quality branch has fixed constants (patch required) | Deferred; users can choose native Performance plus V5's profile |
| Proximity-TLAS sizes (`ProximityTLASSize` 400 m, `ProximityExtendedTLASSize` 800 m, `ProximityTLASBigObject` 15 m) | Read in leaf functions `0x1cf2a20` and `0x1cf2bd0` (proximity-TLAS construction); `ProximityTLASBigObject` also in `0x228f6c0`. Which effects trace the proximity TLAS (`RadianceTlas`=1, `RTAOTlas`=0) and whether shrinking it is safe are not yet traced | **Next round:** promising CPU+GPU lever (fewer TLAS instances); needs AS-path analysis |
| TLAS/BLAS build flags (`RTConfig*`) | Read once at AS setup (`0x1ee97d0`) | Deferred (needs AS-path tracing) |
| CPU-side RT submission | Per-frame RT preparation is vtable-dispatched; static call graph cannot attribute cost | Deferred: needs in-game frame-time data (CPU vs GPU bound) |

## 6. Self-correction log
* The first xref pass dropped all references in leaf functions (no `.pdata`). That briefly suggested most RTGI variables were init-only. The corrected pass (+352 references) shows they are live; only the variables listed above are init-only. Every conclusion here uses the corrected data.
* Context windows that start mid-instruction mis-decode the first lines. Every claim was checked against function-aligned disassembly.

## 7. What only gameplay can tell
1. Real FPS deltas on the RTX 4080 per control, in identical scenes, Normal RT, both RTGI modes.
2. That reflection, shadow and AO parameters are visibly live (the static evidence is per-frame constant-buffer writes).
3. That the console-grid rebuild is a single brief pause and the 40x40 tier persists across saves, loads and RTGI mode switches.
4. The CPU vs GPU bound split (for deciding the next research step).
