## 2. RTGI Shading Frame Budget retirement

**Before**
- Both rows wrote the engine's `RTXGI/Grid1 ShadingRaysPerFrameBudget` (session-only variable, flag 0x201).
- The writes came from `cr01_rt_legacy501.c`, field `CR01_RT_L_BUDGET`, keys `RTQualityShadingBudget` and `RTPerfShadingBudget`.
- Values per preset (Quality/Performance alike):
  - Performance 65536;
  - Balanced 262144;
  - Extreme 524288.

**Now**

| Layer | Change |
|---|---|
| Menu | Both rows removed. The 6 Quick Preset XML entries (3 presets × 2) removed; all other entries are identical to RC5 (`tests/fixtures/v52_presets_rc6.json`). |
| Script | Both Quick Preset blocks removed: 6 config writes and 2 UI refreshes. Both hovers, both greying tags and both ownership-gate entries removed. |
| Runtime | `cr01_rt_legacy501_reload` never reads either key: the field is forced to 0 = Native, exactly like Shading Rays Per Probe since V5.1.0-rc3. The engine variable is never owned or written. Removed from the startup self-check key list. |
| Saved values | Old values left in `[RefinedTracingCR01]` are ignored. Even garbage values cannot invalidate the other RTGI preferences (host test). Nothing is migrated or rewritten. |
| Restoration | The variable is session-only (not saved by the game), so every game start begins with the game's own value. Since the new build never writes it, it behaves as if URT were not installed. |

**Unchanged**
- The other RTGI Quality and Performance rows: Primary, Secondary, Max Probes, AO Quality, Global and Grid1 shading limits.
- Their preset values.
- Probe and ray behaviour.

## 3. Graphics-settings integrity audit

### Static finding (Patch 5.01) [static]

The game's settings save (function at `0x1426e7070`, 24 call sites) does the following:
- It walks every registered engine variable.
- For each one whose **save bit** is set (descriptor flag byte +9, bit 0 = "0x100"), it writes the **live** value into the user document.
- It then writes `dx12user.settings`.

So a raw value written by any mod to such a variable reaches the player's file at the next save. This is the same class of problem as the Ultra+ → Low regression.

### Classification of every RC6 variable

| Row | Variable | Saved by game? | Native graphics menu? |
|---|---|---|---|
| PT: Scene Range | ProximityTLASSize / ProximityExtendedTLASSize | no (0x202) | no |
| PT caustics ×6 | Caustics* | no (0x200/0x201/0x202) | no |
| PT: Skin Bounce Light Desaturation | PTSkinIndirectDesaturation | no (0x202) | no |
| RT/PT: Fog in RT Reflections | RtRadianceShadingFog | no (0x200) | no |
| Terrain Preload Distance | TerrainReadAheadDistance | **yes (0x102)** | **unknown**: needs the game's XML |
| Tree and Bush Draw Distance | FoliageDistanceScale | **yes (0x102)** | **very likely**: the game's own foliage visibility-range setting |
| RC3–RC5 rows: AO Screen-Space Sampling, HBIL, AO Pre-Trace, SSR Assist, Textures Streamed at Once | (5 variables) | **yes (0x100/0x101)** | not believed (unverified) |

### New protection: session-only application [static, offline]

For every row whose variable the game saves, the protection lives in `urt_gfx_core` and `urt_gfx501`:
1. URT first clears that variable's save bit with a 1-byte compare-and-swap.
2. It writes its value only 250 ms later. A save already past the bit test cannot read URT's value.
3. On Native/Auto, Master Off, renderer change, invalid settings or shutdown, URT restores the value first and then the bit.
4. If the game or another mod writes the variable, URT releases it and restores the bit immediately.

**Effect:** while URT owns such a variable, the game's save skips it. The player's own line in `dx12user.settings` stays exactly as it was.

**Fail-safe rules**
- A row whose save byte is not exactly where expected (value at descriptor +0x20, bit set at start) is never owned.
- The same applies to a save byte that someone else has already cleared.

**Tests** (`test_gfx_image_rc6` runs the real adapter on the real `witcher3.exe`)
- After every tick, a saved variable never holds a URT value while its save bit is set.
- Master Off, unknown renderer, invalid input and shutdown leave the image **byte-identical** to the original.

**Still unchanged, reported for completeness**
- Three V5.1.0 rows also write save-flagged variables: AOPretraceQualityLevel (RTGI AO Quality) and PTLateSpecular* (Screen-Space Specular, Specular Checkerboard).
- They are outside this request and use the V5.1.0 code path.

### What is not affected

- The ASI still has no INI writer.
- It opens `dx12user.settings` read-only.
- The script still has exactly 3 `SaveUserSettings` calls, unchanged since RC3, all after a user edit.
- MaxTextureSize, TextureMemoryBudget, TextureMipBias and TextureInFlightBudget are never named by the runtime.

### Native graphics-menu evidence (your installation, WCC kit rev11, read-only) [WCC]

The kit scanned the 21 XML files in `...\bin\config\r4game\user_config_matrix\pc`. Index and copy are in `docs/evidence_rc6/NATIVE_MENU_EVIDENCE/`. The only native file that mentions any URT-owned variable is `graphics.xml` (sha `8f4319e4…`):

- **`FoliageDistanceScale`** is set by every level of the native option `Virtual_FoliageVisibility` ("Foliage Visibility Range": 1 / 1.2 / 1.5 / 1.8 / 1.8), which is tagged `refreshEngine;customPresetIfChanged`.
  - A URT override would change what that option shows, and could switch your graphics preset to Custom.
  - **Tree and Bush Draw Distance therefore stays out of the menu.** It stays compiled in but hidden, and saved values are never read. The game's own option already controls it.
- **`TerrainReadAheadDistance`** appears in no game or mod menu XML.
  - **Terrain Preload Distance is shipped.** It is applied session-only (the game saves this variable, so its save bit is detached while URT owns it).
- None of the five RC3–RC5 saved variables (AO Screen-Space Sampling, HBIL, AO Pre-Trace, SSR Assist, `TextureInFlightCountBudget`) is part of a native option.
- **Independent confirmation of the RC2 root cause:** the native Texture Quality option *does* set `TextureMemoryBudget` and `TextureMipBias`. These are the two variables removed in RC3, which explains the Ultra+ → Low regression.
