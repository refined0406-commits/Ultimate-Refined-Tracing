## 1. Separator repair (permanent fix)

### Cause [static]

`W3OptionsSeparator.width` (ABC method 1653) does the following:
- If the title's measured width is 0, it hides `rightLine`.
- Otherwise it sizes and places both lines, but **never sets `rightLine.visible = true`**.

The separator object is created **once per recycled list row** and reused for every separator and every list refresh. One layout with a 0-width title makes that row's right line disappear for every later heading. Such a layout can come from:
- an unnamed separator on any page;
- a heading measured before its text was laid out.

This explains every RC6 screenshot symptom: the line is missing at first opening, missing after one scroll step, and present or absent depending on which row slot a heading lands in.

RC5 only removed one trigger, URT's own unnamed separators.

### Fix [offline-verified transform]

The fix replaces exactly 14 bytes of that setter with 14 bytes that set `rightLine.visible = (textWidth != 0)` on **every** layout before the original branch:
- every named heading always shows both lines with the original geometry;
- unnamed separators keep the game's original single-line look.

Code length, branch targets and `max_stack` (3) are all unchanged.

**Both copies of the movie are patched** in the original V5.1.0 `panel_ingamemenu.redswf`:
- **Compressed GFx movie (the one RC4 missed).** It is re-encoded as a complete zlib stream of exactly the original length, so no CR2W size, offset or table changes.
- **Uncompressed SWF copy.** Patched in place.

The repo keeps the original file (`9a9f9c5a…`). `build.py` applies `tools/v52_selected/separator_swf_fix.py` and ships `e02ce45d…`.

**Regression test** `test_separator_swf_rc7` [offline]:
- It executes the **real** setter bytecode from both movie copies in a small AVM2 interpreter.
- **Original file:** the defect is reproduced.
- **RC7 file:** both lines appear on every named layout over 93 recycled layouts (unnamed, named and repeated relayouts mixed), with the original geometry, and on a separator created with a hidden right line.
- **File level:** same size; only one 14-byte window changes in each movie.

**Other mods:** this changes the game's own separator component, so every menu benefits. Unnamed separators everywhere are unchanged.

**Limitation:** if another mod (for example Mod Settings Menu Fix) ships its **own** `panel_ingamemenu.redswf` with higher load priority, the game uses that file instead of URT's, and this fix cannot apply. See checklist step 1.

## 3. Tree and Bush Draw Distance (released, session-only)

The variable is `FoliageDistanceScale`. The game saves it (flag 0x102), and its own option `Virtual_FoliageVisibility` (Foliage Visibility Range) also sets it.

**Protection** [static/offline]:
- **Session-only ownership.** URT clears the variable's save bit before writing and restores the value before the bit, so URT's value is never written to `dx12user.settings`.
- **New in RC7: player changes win.** If the game's graphics menu (or another mod) writes the variable, URT releases it, gives the save bit back, and does **not** take it again until the game has written `dx12user.settings`. Your new Foliage Visibility Range level is therefore saved first, and then becomes the native value URT restores. The same rule now applies to all 7 saved rows.
- **Master Off and Native / Auto** restore your currently intended level.
- **Native menu display:** the native option stores its own selection, which matches what you observed in game. Whether the graphics preset ever shows "Custom" is **[in game]**.

**Residual window [static]:** if the game saved within the ~50 ms between a native write and URT's next check, that one save would skip the variable. The native menu saves on leaving the menu, not on the value change, so this is not expected.

**Immersive World:** it binds Grass and FoliageShadow variables, never `FoliageDistanceScale`. CPU: Distant Trees uses separate billboard variables. No overlapping ownership.
