# V5.0.0 pre-release hotfix: crash when changing Game or Gwent Difficulty

* **Branch:** `hotfix/v5.0.0-difficulty-menu`, based on tag `v5.0.0-review` (commit 4c0ed6d).
* **Version:** unchanged at V5.0.0.
* **Status:** **compiled on Windows (kit rev2, 2026-10-21 19:10 UTC). Replacement V5.0.0 packages built and verified offline. Windows gameplay acceptance pending.**

## 1. Findings

### Confirmed at source level
* `game/wcc/RefinedTracingCR01_RTGI3.ws` is the exact source of the shipped `precompiled.rsblob`:
  * source sha `07f8b823…`;
  * blob `3332ffc9…`;
  * V4.3.0 build receipt `RELEASE_V430/PROVENANCE/BUILD_RECEIPT.txt`.
* That blob is byte-identical in V4.3.0, V4.3.1 and V5.0.0. The V5 native-runtime rebuild did not touch WitcherScript, so the reported V4.3.0 behaviour applies to V5.0.0 unchanged.
* The `@wrapMethod(CR4IngameMenu) OnOptionValueChanged` wrapper ran `groupName = mInGameConfigWrapper.GetGroupName(groupId);` as its first statement. This happened for **every** option in every menu, before `wrappedMethod`.
* The blob contains `GetGroupName`, `OnOptionValueChanged` and `RefinedTracingCR01`, so the compiled script has this path.
* This is the only `GetGroupName` call in URT. URT's other menu hooks do no group lookup:
  * `SU_onMenuEntered` (wrap);
  * `OnShowOptionSubmenu` (wrap);
  * the `@addMethod` helpers.
* URT does **not** wrap `OnOptionSelectionChanged`. That event is simply the last one the game logs before the value-change callback.
* SharedUtils' own `OnOptionValueChanged` wrapper calls `wrappedMethod` first and never resolves a group, so it is not implicated.

### Vanilla confirmation (your `C:\RT_BLOB\base\game\gui\main_menu\ingameMenu.ws`, sha fe051467…, copied read-only by kit run 1)
* **Game Difficulty:** vanilla `OnOptionValueChanged` checks `if (groupId == NameToFlashUInt('SpecialSettingsGroupId'))` and returns via `HandleSpecialValueChanged` **before any group lookup**. Its group id is a name hash, not a config group index.
* **Gwent Difficulty:** handled by `if (optionName == 'GwentDifficulty') { FactsSet(...); return true; }`, which also comes **before** vanilla's own `GetGroupName` call.
* So vanilla never resolves a group for either row, while URT's wrapper did so first, for every option. That matches all of the reporter's evidence: a crash only on those rows, only with URT, and the log ending at the menu event with no script error.
* The native crash inside `GetGroupName` itself can only be observed in game. Windows acceptance step 1–2 is the proof.

### Other vanilla options
* Any vanilla row whose group id is not a real config group would hit the same path. The fix covers all of them, because ownership no longer depends on the group id.
* Ordinary vanilla graphics and gameplay options were resolved and then ignored, as before.

## 2. Fix (two hunks, source only)
1. **New `@addMethod(CR4IngameMenu) RT_CR01_IsOwnedOption(optionName: name): bool`.**
   * It is an `||` chain of the 41 interactive Var ids of `RefinedTracing.xml`, the same name-comparison form the wrapper already uses.
   * The 9 separators are excluded because they never raise value events.
2. **The single group lookup is now gated:**
   ```
   groupName = '';
   if (this.RT_CR01_IsOwnedOption(optionName)) {
     groupName = mInGameConfigWrapper.GetGroupName(groupId);
   }
   ```

Everything after the gate is byte-identical:
* the owned stale-preset early return (Master Off);
* `wrappedMethod`;
* preset disengage;
* `RT_CR01_ApplyQuickPreset`;
* `RT_CR01_DisableDependents`;
* `SaveUserSettings`;
* the renderer-eligibility save for `PTEnable`/`EnableRT`/`EnableRtRadiance`/`Virtual_RTShadows`.

| Option | Before | After |
|---|---|---|
| URT option (41) | GetGroupName → processed → saved | identical |
| Same name in another group | GetGroupName → ignored | identical (the group check is kept) |
| Vanilla, incl. Game/Gwent Difficulty | **GetGroupName(special id)** → wrappedMethod | wrappedMethod only, as without URT |
| PTEnable/EnableRT/… | GetGroupName → wrappedMethod → save | wrappedMethod → save (no lookup) |

No change was made to:
* controls, labels, tooltips, separators or translations;
* presets or Master/isolation;
* the ASI, loaders or shaders;
* settings handling or `dx12user.settings`.

The menu XML, locales, `.redswf` and every native file are untouched.
